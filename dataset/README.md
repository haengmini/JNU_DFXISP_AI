# RAW Object Detection Datasets

This directory contains the LOD and PASCALRAW test splits and the derived datasets used for software evaluation and FPGA/HLS experiments. The original data and all derived datasets are local-only data and are not committed to Git. Derived datasets can be regenerated using the commands below.

Last updated: August 13, 2026.

The canonical design rationale is documented in `isppipeline/hls/results/hw-dataset-geometry-2026-08-13.md`. Additional background on the complementary LOD/PASCALRAW evaluation is available in `isppipeline/hls/results/pascalraw-adapter-2026-07-13.md`.

## Dataset Summary

| Directory | Purpose | Frames | RAW Format | Resolution | Approx. Size |
|---|---|---:|---|---|---:|
| `LOD_test/` | Original LOD test split | 100 | Sony camera RAW, 14-bit `.ARW` | 5496 x 3672 visible | 2.0 GB |
| `PASCAL_test/` | Original PASCALRAW test split | 100 | Nikon camera RAW, 12-bit `.NEF` | 6034 x 4012 visible | 2.2 GB |
| `LOD_test_eval/` | Legacy software-evaluation input | 100 | Shift-8 uint16 RGGB | 5472 x 3648 | 5.3 GB |
| `LOD_test_hw/` | FPGA/HLS input | 100 | 12-bit uint16 LE RGGB | 1368 x 912 | 240 MB |
| `PASCAL_test_hw/` | FPGA/HLS input | 100 | 12-bit uint16 LE RGGB | 1368 x 912 | 240 MB |

LOD was captured with a Sony RX100 VII and consists entirely of nighttime or low-light scenes. Its sensor black and white levels are 800 and 16380, respectively. It is used to measure low-light checker recall.

PASCALRAW was captured during daytime with a Nikon D3200. Its sensor black and white levels are 0 and 4095. It complements LOD by measuring false low-light triggers on daytime scenes.

Both sensors use an RGGB Bayer pattern from the origin (`raw_pattern=[[0,1],[3,2]]`, `color_desc=RGBG`).

The original test directories use these project class IDs:

```text
0: person
1: car
2: bicycle
```

The `*_hw` labels use zero-indexed COCO-80 IDs instead: `0=person`, `1=bicycle`, and `2=car`.

## LOD Dataset

The `raw` directory in the LOD test split contains `.ARW` files captured with a Sony camera. Standard image libraries may not be able to open these RAW files directly, so use `rawpy` or another LibRaw-based tool.

The JPG files under `images` were generated by converting the RAW data to RGB so that object detection models can read them. The existing preprocessing pipeline preserves the original aspect ratio and resizes the longest side to 1280 pixels.

## PASCALRAW Dataset

The `raw` directory in the PASCAL test split contains 12-bit `.NEF` files captured with a Nikon D3200. The `images` directory contains the corresponding JPG files for model input and visualization.

The complete PASCALRAW distribution is approximately 150 GB and is distributed as multiple split TAR files. The test split in this project contains 100 selected evaluation images and their corresponding labels.

## FPGA/HLS Dataset Contract

`LOD_test_hw` and `PASCAL_test_hw` have identical dimensions and formats, so both can use the same pipeline width, height, and buffer configuration. Every derived filename stem has a one-to-one match with its source frame.

```text
raw_bin/<stem>.bin   1368 x 912, uint16 little-endian, values 0..4095
                     12-bit RGGB with (0,0)=R, row-major
                     exactly 2,495,232 bytes per frame
labels/<stem>.txt    normalized YOLO: class cx cy width height
                     zero-indexed COCO-80 IDs: 0=person, 1=bicycle, 2=car
preview/<stem>.jpg   nearest-neighbor demosaic and gamma for visual checks only
meta.json            crop origin, black/white levels, and box clip/drop counts
```

| Property | `LOD_test_hw` | `PASCAL_test_hw` |
|---|---|---|
| Source to crop | 5496 x 3672 to 5472 x 3648 at (12, 12) | 6034 x 4012 to 5472 x 3648 at (280, 182) |
| Retained field of view | 100% | Approximately 82% |
| Downsampling | 4x same-color decimation | 4x same-color decimation |
| Label boxes | 530; 29 clipped, 0 dropped | 162; 33 clipped, 2 dropped |
| Low-light RM output | 684 x 456 | 684 x 456 |

The 1368-pixel input width keeps the binned width at 684, below the `MAX_BINNED_W=960` hard bound imposed by `row_r` in `dfxisp_accel.cpp`. It also reduces each frame from approximately 40 MB to 2.44 MB.

Same-color decimation is intentional. A 4x4 same-color average would pre-apply an operation similar to the 2x2 binning performed by `RM_LOW_LIGHT`, reduce noise, and invalidate the July 20, 2026 deployment calibration (`BLC=2`, `dark16`, and `DARK_RATIO_PCT=62`). Measured dark-ratio preservation has a maximum absolute difference of 0.021 percentage points for LOD and 0.067 percentage points for PASCALRAW.

The accelerator consumes 12-bit samples with `RAW12_MAX=4095`. Do not feed the legacy shift-8 representation directly to it: values can reach 65280 and would saturate the entire frame. If a shift-8 view is required, derive it with `(v >> 4) << 8`; this differs from the legacy rounding by at most one code.

## Choosing a Dataset

| Task | Dataset |
|---|---|
| HLS C simulation, FPGA execution, timing, or resource measurements | `LOD_test_hw` and `PASCAL_test_hw` |
| Comparing LOD and PASCALRAW under identical geometry | `LOD_test_hw` and `PASCAL_test_hw` |
| Direct comparison with results produced before July 20, 2026 | `LOD_test_eval` |
| Generating a new derivative or testing another crop/downsampling method | `LOD_test` and `PASCAL_test` |

Do not compare absolute `*_hw` mAP directly with legacy full-resolution results because the resolution changed and the PASCALRAW crop removes approximately 18% of the field of view. Use the hardware datasets for relative comparisons between experiment arms. The selected detector is YOLOv8n; the earlier YOLOv8s cross-validation plan was withdrawn on August 13, 2026.

## YOLO Label Format

Each line in a TXT label file represents one object:

```text
class_id x_center y_center width height
```

The coordinates and dimensions are normalized to the image width and height and therefore range from `0.0` to `1.0`.

## Reading RAW Files

Install `rawpy`:

```bash
pip install rawpy
```

Basic example for converting an ARW or NEF file to RGB:

```python
from pathlib import Path

import rawpy
from PIL import Image

raw_path = Path("dataset/LOD_test/raw/DSC01144.ARW")

with rawpy.imread(str(raw_path)) as raw:
    rgb = raw.postprocess(
        use_camera_wb=True,
        no_auto_bright=False,
        output_bps=8,
    )

Image.fromarray(rgb).save("converted.jpg", quality=95)
```

The same code can be used with PASCALRAW `.NEF` files.

## Model Input Considerations

- The current YOLOv8 and MobileNet SSDLite training pipelines use RGB inputs such as JPG or PNG files.
- Direct `.ARW` or `.NEF` input requires a data loader that performs RAW decoding and either RGB conversion or Bayer tensor conversion.
- RAW and JPG files must share the same filename stem to use the existing YOLO TXT labels directly.
- YOLO coordinates remain valid when RAW conversion applies proportional resizing without cropping.
- Bounding-box coordinates must be recalculated if cropping is applied.

## Regenerating the FPGA/HLS Datasets

Run the builder from the `isppipeline/hls` directory:

```bash
cd isppipeline/hls
python3 tools/build_hw_dataset.py --selftest

python3 tools/build_hw_dataset.py \
    --raw-dir ../../dataset/LOD_test/raw \
    --labels-dir ../../dataset/LOD_test/labels \
    --out ../../dataset/LOD_test_hw --preview 3

python3 tools/build_hw_dataset.py \
    --raw-dir ../../dataset/PASCAL_test/raw \
    --labels-dir ../../dataset/PASCAL_test/labels \
    --out ../../dataset/PASCAL_test_hw --preview 3
```

The LOD and PASCALRAW conversions take approximately 40 and 60 seconds for 100 frames. They require `rawpy` and `numpy`; `Pillow` is required only for previews. The builder analytically asserts that the `(0,0)` quad remains RGGB after decimation and fails on the affected frame if the Bayer phase is incorrect.

Use `--limit N` to process the first N frames. Use `--min-visible F` to drop boxes whose visible area after cropping is below fraction F of their original area. Its default is 0.25, which prevents undetectable ground-truth fragments from becoming false negatives.

## Known Source-Data Alignment Notes

- LOD labels are based on the 5496 x 3672 visible image, while legacy `LOD_test_eval/raw_bin` data is 5472 x 3648, producing a 0.2-0.4% offset. The hardware builder resolves this by interpreting labels in visible-image coordinates and remapping them to the crop.
- PASCALRAW labels are based on an exact 600 x 400, 3:2 reference, while the RAW image aspect ratio is 1.5040. The resulting 0.27% anisotropy remains in `PASCAL_test_hw`.
- `LOD_test_eval/convert_errors.log` is empty; the legacy conversion reported no errors.

## Cache Files

`labels.cache` is generated automatically by Ultralytics YOLO to speed up label discovery. It is not part of the original dataset and can be deleted and regenerated safely. Excluding it when compressing or sharing a dataset is recommended.
